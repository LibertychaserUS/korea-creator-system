# 演示流程

用样例数据（fixture）走完整闭环：抓 → 转 → 筛 → 派 → 导出。约 10 分钟。启动步骤见 `HANDOFF.md`。

账号（密码 `Kcs!demo2026`）：`ops@kcs.local`（运营）、`selector@kcs.local`（选人）、`devops@kcs.local`（运维）、`admin@kcs.local`（全部）。

## 0. 宣传站（7005）— 1 分钟

打开 `/zh-CN/`。讲三件事：数据从哪来（路线 A / B，不自建抓取）、指标怎么读（六组、量级、健康、同源同量级分位）、筛选方案替代评分。切 `en` / `ko` 看三语，切深色。

## 1. 运营端 → 数据源（7002）— 3 分钟

1. 登录 `ops@kcs.local`，进「数据源」。
2. 三张适配器卡：蒲公英（路线 A，凭证 `PGY_ACCESS_TOKEN` + 网关）、千瓜、新红（路线 B）。没配凭证 → 卡上"未配置"，表单下方提示将返回样例数据。
3. 选蒲公英，窗口 30 天，关键词"护肤"，粉丝 1 万–50 万，健康只勾"优秀"，条数 50 → 运行。
4. 结果条显示"已加入队列 · 任务号"；任务表 3 秒内从 `排队中` → `进行中` → `完成`，状态下方"第 N 页 · 调用 M 次"，来源徽标带"样例"。
5. 讲：原始 JSON 原样落 `creator_raw`；转换层出 33 个指标，平台不给的是"—"；每次抓取一条快照。
6. 可选：把 `ingest_sources.quota` 改成 1 再跑一次，演示 `部分完成` + 续跑时间 + 重试按钮。

## 2. 运营端 → 审核发布 — 1 分钟

概览页看到新抓的博主是草稿；进审核通过一两个，发布。讲：只有已发布的进选人端。

## 3. 选人端 → 博主池（7004）— 3 分钟

1. 登录 `selector@kcs.local`。池表默认方案：粉丝、阅读中位数、互动中位数、互动率、CPE…每格颜色是**同源同量级**分位，悬停看"同源同量级 N 人 · 蒲公英 · 腰部"。
2. 新建方案「护肤腰部性价比」：量级 = 腰部；健康 = 优秀；CPE ≤ 3；收藏/点赞 ≥ 0.8；排序 CPE 升序；高亮 CPE ≤ 2 绿、互动率 < 2% 琥珀；显示列加 图文一口价、搜索流量占比。保存。
3. 表格立刻收缩；方案 chip 出现在方案栏，刷新仍在。讲：这就是"评分"——用平台语言写条件，可保存、有版本，不算分。

## 4. 博主详情 — 1 分钟

点一个博主：身份条（量级、健康、来源、同源同量级 N 人）→ 趋势卡（粉丝 / 阅读 / 互动率 / CPE 四条折线，30 / 90 切换，展开快照表）→ 六组指标卡（分位条）→ 受众画像 → 数据来源卡（每个来源的 ID 与最后抓取时间；如果有归并会看到两行）。

## 5. 项目分派与导出 — 1 分钟

新建项目「9 月护肤投放」→ 从池里分派 3 人 → 项目页 KPI（人数、CPE 中位、互动率中位、健康分布）→ 导出 CSV（列 = 方案显示列）。

## 6. 运维端（7003）— 30 秒

登录 `devops@kcs.local`：任务状态分布、流水线（每个来源今日调用 / 配额）、审计流（刚才的登录、发布、分派都在）。`失败` / `部分完成` 的任务可重试。
