# 数据字典

库：Postgres `kcs`（API 自有）。身份数据不在这里，在 TinyShip 的 `tinyship` 库（`user` / `session` / `account` / `verification`，由 `libs/database` 的 drizzle schema 管理）。

迁移：`apps/api/src/migrations/000N_*.sql`，按文件名顺序执行，已应用的记录在 `schema_migrations(version, applied_at)`。`0001_baseline` 幂等基线 → `0002_tinyship_identity`（删 sessions / password_hash / 镜像 "user"）→ `0003_ingest_queue` → `0004_creator_metrics_history` → `0005_creator_sources` → `0006_merge_duplicate_xhs_ids`（存量重复小红书号无损归并）→ `0007_ingest_dead_letters` → `0008_base_reference_data` → `0009_published_snapshot`（`metrics_locked_at`；存量已发布博主补一份快照）→ `0010_list_indexes`（身份查找与各分页列表的索引）→ `0011_drop_unused_legacy`（删无人使用的基线对象，见文末）→ `0020_published_snapshot_heal`（已发布的行都带发布快照，读路径不再补写）→ `0021_metric_keys_and_health`（指标键改名、健康等级两级 + `lowActive`，见 03）→ `0022_prices_minor_units`（报价最小单位 + 币种枚举 + 汇率）→ `0023_creator_published`（选人池窄表与分位）→ `0024_saved_query_revisions`（方案可见范围、修改记录、收起）→ `0025_creator_events`（结果事件）→ `0026_legacy_metric_keys`（`0021` 之后又写进来的旧指标键，以及保存的方案里的旧键，改成 `cpr` / `completionRate`）→ `0040_split_cross_source_merges`（拆开旧规则按供应商 id 误合并的博主）→ `0041_source_quota_time_zone`（`ingest_sources.quota_tz`）→ `0042_normalize_xhs_ids`（小红书号规范化、同号合并、唯一索引、`creator_merges`）→ `0043_source_signals`（`creators.source_signals`、`creator_metrics_history.signals`；残留的健康等级 `excellent` 改标 `healthy`）→ `0044_daily_tasks`（`ingest_daily_runs`）→ `0045_raw_payload_dedup`（原文按内容只存一份：`raw_payloads`，lz4）→ `0046_value_tiers`（快照与原文的价值分层标签）→ `0047_ingest_scheduler`（刷新统计、实质变化、首个任务、保存的发现条件、调度状态）→ `0048_rate_buckets`（每个来源的限速令牌桶状态）→ `0049_snapshot_per_day`（快照按北京日期每天一份：`snapshot_day`、唯一索引，存量同日多份并成当天最后一份）→ `0050_data_status`（连续未取到次数、平台上已找不到的标记与确认、与发布快照相比的变化、刷新任务已见过的 id）→ `0051_name_search`（昵称模糊搜索：`name_norm` / `name_grams` 生成列、GIN 索引与 `kcs_name_*` 函数）→ `0052_job_retention_indexes`（可选的已结束任务清理用到的两个索引）。号段：`0020`–`0039` 博主池 / 分位 / 方案，`0040`–`0059` 抓取与数据质量，`0060`–`0079` 运维端与字典；全部可重复执行。

多副本同时启动时，迁移先拿 `pg_advisory_lock(4912734)`（会话级，专用连接），后到的副本等锁、发现版本都已应用后什么也不做。

## 核心链路的表

```
ingest_jobs ──(worker)──▶ creator_raw ──normalize──▶ creators.metrics
                                     └──────────────▶ creator_metrics_history（每人每源每天一条）
                                     └──────────────▶ creator_sources（(source, external_id) → creator）
creators（released）──发布 / 下架 / 触发器──▶ creator_published ──SQL 筛选 / 排序 / 游标──▶ 选人端博主池
saved_queries ──（与契约 applySavedQuery 逐行一致）──────────────────────────▶ 方案结果
发布 / 下架 / 分派 / 移出 / 导出 / 查看详情 ──▶ creator_events（只追加）
projects / assignments / shortlist_items ──▶ 项目与候选
```

### creators — 博主主记录

| 列 | 说明 |
|---|---|
| `id` | 主键 |
| `creator_key` | 唯一键。`xhs:<userId>`（蒲公英 userId）；供应商记录归并到同一博主后沿用已有键 |
| `display_name`, `xhs_id`, `avatar_key` | 身份。`xhs_id` 是小红书号，是跨来源归并的依据；任何写入都由触发器折成一种写法（去首尾空白、全角转半角、小写，空串为 NULL），一个号只能属于一个博主（部分唯一索引 `creators_xhs_id_key`） |
| `status` | `draft` → `ready` → `released`（选人端只看 `released`）。运营端的「待审核 / 已发布 / 已下架」由 `status` + `metrics_locked_at` 推出（契约 `creatorStage`）：未发布且从没发布过 = 待审核，`released` = 已发布，未发布但有快照时间 = 已下架 |
| `needs_review`, `qc_notes`, `note`, `label` | 运营审核 |
| `followers`, `regions[]`, `verticals[]` | 从 `metrics` 提出来方便过滤 |
| `source`, `external_id` | **最近一次**抓到这条记录的来源；全部来源看 `creator_sources` |
| `metrics` jsonb | **最新**一条 `CreatorMetrics`（口径见 03）。抓取、死信重放、表格导入、手工编辑都只写这里 |
| `metrics_window` | 30 / 90 |
| `metrics_fetched_at` | 最新快照时间 |
| `source_signals` jsonb | 最近一次来源给的、共享指标装不下的事实（契约 `SourceSignals`：健康等级两级、低活跃、平台同类排位、完播率 / 3 秒阅读率、合作笔记总数、进店 UV 与单价、各字段覆盖天数）。表格导入不改它 |
| `metrics_locked` jsonb | **发布时**的指标快照：发布（审核通过并发布 / 下架后重新发布）那一刻从 `metrics` 复制。选人端博主池的筛选、排序、分位、项目名单与导出一律读它；抓取永远不碰它。已在池中再点发布不刷新 |
| `metrics_locked_at` | 快照时间。为空 = 从没发布过 |
| `metrics_locked_fetched_at` | 发布快照里的数字是**什么时候抓的**（不是什么时候发布的）；超过 60 天的不排位。`0023` 之前发布的取「抓取时间与发布时间里较早的」作估计 |
| `available_from/to`, `rating` | 运营手填 |
| `last_ingest_job_id` | 最近写入它的任务 |
| `first_ingest_job_id` | 第一次把它带进来的任务（调度器按此统计「发现」的收益） |
| `platform_missing_at`, `platform_missing_confirmed_at` | 「平台上已找不到」：任一来源连续 `PLATFORM_MISSING_AFTER`（默认 3）次按 id 刷新都没取到时标记，博主池应把它排除，等运营确认（`keep` 清掉 / `gone` 记确认时间）；之后任何一次抓到它自动清掉。不删数据（`docs/04` §数据状态） |
| `republish_changes[]`, `republish_checked_at` | 最新数字与发布快照 `metrics_locked` 相比超过容差的指标，以及算的时间（每次写入与每日任务 `data-status` 重算）。`republish_checked_at` 早于 `metrics_locked_at` 时视为过期（刚重新发布过） |
| `name_norm`, `name_grams[]` | 由 `display_name` 生成（改名自动跟着变）：规范化昵称（NFKC、小写、去空白与标点）与搜索用的短片段——汉字 / 韩文音节两两相连（`c:`）、韩文字母（`j:`）、初声（`i:`，支持「ㅈㅅ」这种只打初声的搜索）、宽松罗马字（`r:`，`Jisoo` / `Jisu` / `지수` 折成同一个）。GIN 索引 `creators_name_grams_idx`。中文拼音暂不支持（需要字典） |


### creator_raw — 平台原样 JSON

| 列 | 说明 |
|---|---|
| `creator_id` → creators | |
| `source` | `pugongying` / `qiangua` / `xinhong` |
| `external_id` | 平台侧 ID |
| `fetched_at` | |
| `payload_hash` → raw_payloads | 这次抓到的原文。内容完全相同的多次抓取指向同一份 |
| `payload` jsonb | 旧数据的内联原文（迁移 0045 已全部搬进 `raw_payloads` 并置空）；新写入恒为 NULL。读原文一律 `COALESCE(creator_raw.payload, raw_payloads.payload)` |

每次抓取仍各记一行（谁、哪个来源、什么时候），所以「哪天抓到过什么」可以完整还原；只是内容相同的原文只存一份。索引 `(creator_id, fetched_at desc)`、`(creator_id, source, fetched_at desc, id desc)`、`(payload_hash)`。运营端 `GET /api/ingest/raw/:creatorId` 直接看这里。现阶段全部保留；只有运维显式设 `RETENTION_RAW_PER_SOURCE` 为正数时，每日清理才按（博主，来源）删旧（`docs/04` §保留期限）；`creator_metrics_history` 永远不清。

### raw_payloads — 原文内容（按内容去重）

| 列 | 说明 |
|---|---|
| `hash` bytea | 主键，`sha256(payload::text)`。jsonb 的文本是规范形式（键序、空白无关），同样的 JSON 必得同一个值 |
| `payload` jsonb | 适配器返回的原始记录，不做任何改写。蒲公英详情补全后 `dataSummary` / `fansSummary` / `notesRate` / `fansProfile` 合并在同一条里，另记 `kcsWindow` / `kcsDateType`（当次请求的窗口与发出的 `dateType`）。列压缩 lz4（服务器不支持时退回 pglz） |
| `bytes` | 原文字节数（`octet_length(payload::text)`），容量统计用 |
| `first_seen_at` | 第一次见到这份内容的时间 |

只有打开原文清理（`RETENTION_RAW_PER_SOURCE`）时，清完 `creator_raw` 后才会把没人再指向的内容删掉；默认全留。

### creator_metrics_history — 指标快照

| 列 | 说明 |
|---|---|
| `id` | |
| `creator_id` → creators (cascade) | |
| `source`, `window`, `fetched_at`, `job_id` | 当天最后一次抓取的时间与任务 |
| `snapshot_day` date | 生成列 = `fetched_at` 的北京日期；`(creator_id, source, window, snapshot_day)` 唯一 |
| `metrics` jsonb | 当次 normalize 出的 `CreatorMetrics` |
| `signals` jsonb | 当次的 `SourceSignals`（见 `creators.source_signals`） |
| `material_change`, `changed_metrics[]` | 与同一来源、同一窗口、更早一天的最后一份快照相比数字是否实质变化（超过各指标容差，见 `docs/04` §价值分层），以及哪些指标变了；第一份为 NULL |
| `value_tier`, `tier_features`, `tiered_at` | 价值分层标签（只打标签，不据此删除）：`pinned` 钉住 / `change_point` 变化点 / `downsample` 可降采样 / `cold` 可冷存；`tier_features` = `{ reasons, changed, deltas, ageDays }`。每日任务 `value-tiers` 重算，见 `docs/04` §价值分层。`creator_raw` 有同样三列 |

同一博主、同一来源、同一窗口每个北京日期一条：当天再抓一次覆盖这一条（原文 `creator_raw` 每次仍各留一条，所以不丢测量，只是去掉同日重复的解析结果）；比这一条更早的抓取晚到时不覆盖。`creators.metrics` 只是最新一条。趋势、涨粉、CPE 变化都从这里读，不重算。索引 `(creator_id, fetched_at desc)`。

| `creator_id` → creators | |
| `first_seen_at`, `last_seen_at` | |
| `refresh_visits`, `refresh_changes`, `observed_days` | 刷新统计：与上一份比较过几次、几次有实质变化、累计间隔天数 |

### creator_merges — 合并留档

两条博主因同一个小红书号合并时，被并掉的那一行原样留在这里，不丢任何东西。

| 列 | 说明 |
|---|---|
| `merged_id` / `into_id` | 被并掉的博主 id / 保留的博主 id |
| `reason` | 如 `xhs_id:cheongdam_skin` |
| `merged_row` | 被并掉那行 `creators` 的完整 JSON |
| `conflicts` | 没能移过去的关联行（目标已有一条相同的，如同一个分类）：`[{table, row}]` |

### ingest_source_usage — 日配额

`(source, day)` 主键，`day` 是来源 `quota_tz` 时区的日期；`calls` 累计当日调用次数（每页 / 每次详情补全 +1）。演示数据退回的调用记回取用时那一天。

### ingest_rate_buckets — 限速令牌桶

`source` 主键；`capacity` = 当时的 `rate_limit`（次/分钟），`tokens` 为 `updated_at` 那一刻剩余的令牌（小数，按时间连续回填）。只是运行状态，seed 重置会清空。

### creator_published — 选人池窄表（`0023`）

每个已发布、未删除的博主一行，是 `creators` + 分类 / 合作 / 报价的投影：发布、下架、拉黑时在同一事务里写，随时可由 `refreshPublished` 从源表重建，删掉一行不丢数据。选人端博主池与方案结果**只读这张表**。

| 列 | 说明 |
|---|---|
| `creator_id` → creators (cascade) | 主键 |
| `group_key` | 比较组 `source\|window\|form`（缺失写 `-`），如 `pugongying\|30\|image` |
| `source`, `window`, `content_form`, `tier` | 组的三个维度与粉丝层级 |
| `health`, `low_active` | 健康等级（两级）与低活跃标记 |
| `display_name`, `creator_key`, `xhs_id`, `avatar_key`, `external_id` | 身份，供搜索与列表 |
| `regions[]`, `verticals[]`, `categories[]`, `blacklisted` | 过滤；`blacklisted` 的行保留但列表与排位都跳过 |
| `collab_count`, `collab_brands[]`, `coop_brands[]` | 合作次数（来自 `collaborations`）与品牌 |
| `price_currency`, `price_min_minor`, `price_max_minor`, `price_fx`, `price_unit` | 手填报价（最小单位 + 汇率） |
| `metrics` jsonb | 发布快照（已并入粉丝、报价、派生值） |
| `m_<指标>` float8 | 每个数值指标一列（`m_cpe`、`m_read_median` …），筛选与排序直接用；常用排序键有 `(m_x DESC/ASC NULLS LAST, creator_id COLLATE "C") WHERE NOT blacklisted` 索引 |
| `p_<指标>` smallint | 预先算好的分位（十分位整数，0–1000），只给有好坏方向的指标 |
| `ranks` jsonb | 每个指标的排位详情：档位、可比人数、粉丝范围、平台 / 本库 |
| `fetched_at`, `latest_fetched_at`, `published_at`, `ranked_at` | 快照抓取时间、最新抓取时间、发布时间、最近一次排位时间 |

触发器：`creators`、`creator_categories`、`collaborations`、`prices` 变化时同步窄表里的名字、地区、分类、合作、报价；拉黑或行被删时把组记进 `cohort_dirty_groups`。

| 附表 | 说明 |
|---|---|
| `cohort_dirty_groups(group_key, marked_at)` | 待重排的组；启动与定时刷新时处理 |
| `cohort_calibration(source_key, target, required, method, pool_size, basis, computed_at)` | 每个来源的目标可比人数与自助法依据（03「同类分位」），运维端 `/api/dev/cohorts` 展示 |
| `cohort_reference_lines(group_key, tier, metric, n, p25, p50, p75, computed_at)` | 组 × 层级 × 指标的 25 / 50 / 75 分位，≥ 30 个当前值才写 |

| 列 | 说明 |
|---|---|

### saved_query_revisions — 方案修改记录（`0024`）

`(query_id, version)` 主键，每个版本一行：该次修改后的 `name`、`visibility`、`spec`，`action`（`create` / `update` / `archive` / `restore`），`edited_by`、`edited_at`。`0024` 之前的方案把当时的状态记为第一条已知版本。

### creator_events — 结果事件（`0025`）

博主进池之后发生了什么，给分位自动校准与抓取调度（「这次发现值不值」）用，**不参与排序**。只追加，不改不删。

| 列 | 说明 |
|---|---|
| `id` bigserial | |
| `kind` | `publish` / `unpublish` / `assign` / `unassign` / `export` / `detail_view` |
| `creator_id` | **不设外键**：博主被归并删掉后历史仍在 |
| `org_id`, `actor_id`, `project_id` | 谁、在哪个项目里 |
| `source` | 事件发生时博主的数据来源 |
| `context` jsonb | 如发布 `{ republish }`、导出 `{ projectId, locale }` |
| `occurred_at` | |

发布、下架、分派、移出、导出与动作本身在同一事务里写；同一人 10 分钟内重复打开同一博主详情只记一次（`DETAIL_VIEW_DEDUPE_MINUTES`），查看记录写失败不影响页面。读取用 `apps/api/src/http/events.ts` 的 `readEvents` 或直接查表；索引 `(creator_id, occurred_at)`、`(kind, occurred_at)`。

## 项目与候选

| 表 | 说明 |
|---|---|
| `orgs` | 组织（选人公司 / 平台） |

| `assignments` | 项目 × 博主，`status`（assigned / removed）、`assigned_by`、`note`、`pool_gone`（博主被下架后标记） |

| `reviews` | 运营审核记录 |
| `assets` | 头像等上传（无对象存储时 bytes 落库） |
| `audit_logs` | 动作审计：`actor_id`、`action`、`entity_type/id`、`summary`；默认全留；设 `RETENTION_AUDIT_DAYS=N` 才删 N 天前的 |
