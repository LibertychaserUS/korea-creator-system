# 数据字典

库：Postgres `kcs`（API 自有）。身份数据不在这里，在 TinyShip 的 `tinyship` 库（`user` / `session` / `account` / `verification`，由 `libs/database` 的 drizzle schema 管理）。

迁移：`apps/api/src/migrations/000N_*.sql`，按文件名顺序执行，已应用的记录在 `schema_migrations(version, applied_at)`。`0001_baseline` 幂等基线 → `0002_tinyship_identity`（删 sessions / password_hash / 镜像 "user"）→ `0003_ingest_queue` → `0004_creator_metrics_history` → `0005_creator_sources` → `0006_merge_duplicate_xhs_ids`（存量重复小红书号无损归并）→ `0007_ingest_dead_letters` → `0008_base_reference_data` → `0009_published_snapshot`（`metrics_locked_at`；存量已发布博主补一份快照）→ `0010_list_indexes`（身份查找与各分页列表的索引）→ `0011_drop_unused_legacy`（删无人使用的基线对象，见文末）→ `0020_published_snapshot_heal`（已发布的行都带发布快照，读路径不再补写）→ `0021_metric_keys_and_health`（指标键改名、健康等级两级 + `lowActive`，见 03）→ `0022_prices_minor_units`（报价最小单位 + 币种枚举 + 汇率）→ `0023_creator_published`（选人池窄表与分位）→ `0024_saved_query_revisions`（方案可见范围、修改记录、收起）→ `0025_creator_events`（结果事件）。`0020`–`0039` 号段归博主池 / 分位 / 方案，全部可重复执行。

多副本同时启动时，迁移先拿 `pg_advisory_lock(4912734)`（会话级，专用连接），后到的副本等锁、发现版本都已应用后什么也不做。

## 核心链路的表

```
ingest_jobs ──(worker)──▶ creator_raw ──normalize──▶ creators.metrics
                                     └──────────────▶ creator_metrics_history（每次一条）
                                     └──────────────▶ creator_sources（(source, external_id) → creator）
creators（released）──发布 / 下架 / 触发器──▶ creator_published ──SQL 筛选 / 排序 / 游标──▶ 选人端博主池
saved_queries ──（与契约 applySavedQuery 逐行一致）──────────────────────────▶ 方案结果
发布 / 下架 / 分派 / 移出 / 导出 / 查看详情 ──▶ creator_events（只追加）
projects / assignments / shortlist_items ──▶ 项目与候选
```

### creators — 博主主记录

| 列 | 说明 |
|---|---|
| `id` | 主键 |
| `creator_key` | 唯一键。`xhs:<userId>`（蒲公英 userId）；供应商记录归并到同一博主后沿用已有键 |
| `display_name`, `xhs_id`, `avatar_key` | 身份。`xhs_id` 是小红书号，是跨来源归并的依据 |
| `status` | `draft` → `ready` → `released`（选人端只看 `released`）。运营端的「待审核 / 已发布 / 已下架」由 `status` + `metrics_locked_at` 推出（契约 `creatorStage`）：未发布且从没发布过 = 待审核，`released` = 已发布，未发布但有快照时间 = 已下架 |
| `needs_review`, `qc_notes`, `note`, `label` | 运营审核 |
| `followers`, `regions[]`, `verticals[]` | 从 `metrics` 提出来方便过滤 |
| `source`, `external_id` | **最近一次**抓到这条记录的来源；全部来源看 `creator_sources` |
| `metrics` jsonb | **最新**一条 `CreatorMetrics`（口径见 03）。抓取、死信重放、表格导入、手工编辑都只写这里 |
| `metrics_window` | 30 / 90 |
| `metrics_fetched_at` | 最新快照时间 |
| `metrics_locked` jsonb | **发布时**的指标快照：发布（审核通过并发布 / 下架后重新发布）那一刻从 `metrics` 复制。选人端博主池的筛选、排序、分位、项目名单与导出一律读它；抓取永远不碰它。已在池中再点发布不刷新 |
| `metrics_locked_at` | 快照时间。为空 = 从没发布过 |
| `metrics_locked_fetched_at` | 发布快照里的数字是**什么时候抓的**（不是什么时候发布的）；超过 60 天的不排位。`0023` 之前发布的取「抓取时间与发布时间里较早的」作估计 |
| `available_from/to`, `rating` | 运营手填 |
| `last_ingest_job_id` | 最近写入它的任务 |


### creator_raw — 平台原样 JSON

| 列 | 说明 |
|---|---|
| `creator_id` → creators | |
| `source` | `pugongying` / `qiangua` / `xinhong` |
| `external_id` | 平台侧 ID |
| `fetched_at` | |
| `payload` jsonb | 适配器返回的原始记录，不做任何改写。蒲公英详情补全后 `dataSummary` / `fansSummary` / `notesRate` / `fansProfile` 合并在同一条里 |

索引 `(creator_id, fetched_at desc)` 与 `(creator_id, source, fetched_at desc, id desc)`。运营端 `GET /api/ingest/raw/:creatorId` 直接看这里。每个（博主，来源）只保留最新 `RETENTION_RAW_PER_SOURCE`（默认 10）条，由每日清理删旧（`docs/04` §保留期限）；`creator_metrics_history` 不清。

### creator_metrics_history — 指标快照

| 列 | 说明 |
|---|---|
| `id` | |
| `creator_id` → creators (cascade) | |
| `source`, `window`, `fetched_at`, `job_id` | |
| `metrics` jsonb | 当次 normalize 出的 `CreatorMetrics` |

每次 ingest 成功写一条；`creators.metrics` 只是最新一条。同一博主同一天同源多次抓取只保留最新。趋势、涨粉、CPE 变化都从这里读，不重算。索引 `(creator_id, fetched_at desc)`。

### creator_sources — 身份归并

| 列 | 说明 |
|---|---|
| `source`, `external_id` | 主键 |
| `creator_id` → creators | |
| `first_seen_at`, `last_seen_at` | |

ingest 时按 (source, external_id) 找链接 → 没有则按 `creators.xhs_id = 规范化后的 xhsId` 归并 → 都没有才新建。归并时 `creators.source/external_id` 指向最近来源，旧链接不丢。

### ingest_source_usage — 日配额

`(source, day)` 主键，`calls` 累计当日调用次数（每页 / 每次详情补全 +1）。

### creator_published — 选人池窄表（`0023`）

每个已发布、未删除的博主一行，是 `creators` + 分类 / 合作 / 报价的投影：发布、下架、拉黑时在同一事务里写，随时可由 `refreshPublished` 从源表重建，删掉一行不丢数据。选人端博主池与方案结果**只读这张表**。

| 列 | 说明 |
|---|---|
| `creator_id` → creators (cascade) | 主键 |
| `group_key` | 比较组 `source\|window\|form`（缺失写 `-`），如 `pugongying\|30\|image` |
| `source`, `window`, `content_form`, `tier` | 组的三个维度与粉丝层级 |
| `health`, `low_active` | 健康等级（两级）与低活跃标记 |
| `display_name`, `creator_key`, `xhs_id`, `avatar_key`, `external_id` | 身份，供搜索与列表 |
| `regions[]`, `verticals[]`, `categories[]`, `blacklisted` | 过滤；`blacklisted` 的行保留但列表与排位都跳过 |
| `collab_count`, `collab_brands[]`, `coop_brands[]` | 合作次数（来自 `collaborations`）与品牌 |
| `price_currency`, `price_min_minor`, `price_max_minor`, `price_fx`, `price_unit` | 手填报价（最小单位 + 汇率） |
| `metrics` jsonb | 发布快照（已并入粉丝、报价、派生值） |
| `m_<指标>` float8 | 每个数值指标一列（`m_cpe`、`m_read_median` …），筛选与排序直接用；常用排序键有 `(m_x DESC/ASC NULLS LAST, creator_id COLLATE "C") WHERE NOT blacklisted` 索引 |
| `p_<指标>` smallint | 预先算好的分位（十分位整数，0–1000），只给有好坏方向的指标 |
| `ranks` jsonb | 每个指标的排位详情：档位、可比人数、粉丝范围、平台 / 本库 |
| `fetched_at`, `latest_fetched_at`, `published_at`, `ranked_at` | 快照抓取时间、最新抓取时间、发布时间、最近一次排位时间 |

触发器：`creators`、`creator_categories`、`collaborations`、`prices` 变化时同步窄表里的名字、地区、分类、合作、报价；拉黑或行被删时把组记进 `cohort_dirty_groups`。

| 附表 | 说明 |
|---|---|
| `cohort_dirty_groups(group_key, marked_at)` | 待重排的组；启动与定时刷新时处理 |
| `cohort_calibration(source_key, target, required, method, pool_size, basis, computed_at)` | 每个来源的目标可比人数与自助法依据（03「同类分位」），运维端 `/api/dev/cohorts` 展示 |
| `cohort_reference_lines(group_key, tier, metric, n, p25, p50, p75, computed_at)` | 组 × 层级 × 指标的 25 / 50 / 75 分位，≥ 30 个当前值才写 |

### saved_queries — 筛选方案

| 列 | 说明 |
|---|---|
| `org_id` → orgs | 方案归属组织 |
| `name`, `version` | 每次真正有变化的保存 `version + 1`；什么都没改的保存不加 |
| `spec` jsonb | `SavedQuery`：`sources`、`tiers`、`health`、`regions`、`brandsAny`、`categories`、`hasCollaborated`、`collabCountMin/Max`、`search`、`filters[]`、`groups[]`（「满足其一」/「排除」条件组）、`sort`、`highlights[]`、`columns[]`、`serviceFee` |
| `visibility` | `private`（我的方案，只有作者看得到）/ `team`（团队方案，组织内都看得到，默认） |
| `created_by`, `updated_by` | 作者、最后修改人 |
| `archived_at`, `archived_by` | 删除 = 收起：写这两列，可恢复；不物理删除 |

### saved_query_revisions — 方案修改记录（`0024`）

`(query_id, version)` 主键，每个版本一行：该次修改后的 `name`、`visibility`、`spec`，`action`（`create` / `update` / `archive` / `restore`），`edited_by`、`edited_at`。`0024` 之前的方案把当时的状态记为第一条已知版本。

### creator_events — 结果事件（`0025`）

博主进池之后发生了什么，给分位自动校准与抓取调度（「这次发现值不值」）用，**不参与排序**。只追加，不改不删。

| 列 | 说明 |
|---|---|
| `id` bigserial | |
| `kind` | `publish` / `unpublish` / `assign` / `unassign` / `export` / `detail_view` |
| `creator_id` | **不设外键**：博主被归并删掉后历史仍在 |
| `org_id`, `actor_id`, `project_id` | 谁、在哪个项目里 |
| `source` | 事件发生时博主的数据来源 |
| `context` jsonb | 如发布 `{ republish }`、导出 `{ projectId, locale }` |
| `occurred_at` | |

发布、下架、分派、移出、导出与动作本身在同一事务里写；同一人 10 分钟内重复打开同一博主详情只记一次（`DETAIL_VIEW_DEDUPE_MINUTES`），查看记录写失败不影响页面。读取用 `apps/api/src/http/events.ts` 的 `readEvents` 或直接查表；索引 `(creator_id, occurred_at)`、`(kind, occurred_at)`。

## 项目与候选

| 表 | 说明 |
|---|---|
| `orgs` | 组织（选人公司 / 平台） |
| `projects` | 项目：`org_id`、`name`、`note`、`status` |
| `assignments` | 项目 × 博主，`status`（assigned / removed）、`assigned_by`、`note`、`pool_gone`（博主被下架后标记） |
| `shortlist_items` | 组织级候选名单 |
| `categories` / `creator_categories` | 分类字典（三语名、启用、前台可见）与博主分类 |
| `collaborations` / `prices` | 运营手填的合作与报价补充。`prices` 金额存最小单位 `amount_min_minor` / `amount_max_minor`（bigint），`currency` 只收 `CNY` / `USD` / `KRW`，外币可带 `fx_to_cny` + `fx_recorded_at`；旧的 `amount_min` / `amount_max` 是只读生成列 |
| `reviews` | 运营审核记录 |
| `assets` | 头像等上传（无对象存储时 bytes 落库） |
| `audit_logs` | 动作审计：`actor_id`、`action`、`entity_type/id`、`summary`；保留 `RETENTION_AUDIT_DAYS`（默认 365）天 |

## 身份

| 表 | 库 | 说明 |
|---|---|---|
| `user`, `session`, `account`, `verification` | tinyship | better-auth 管理；KCS 角色存在 `user.role` |
| `users` | kcs | **profile 镜像**（id / email / role / display_name / org_id），API 每次校验会话后 upsert，只为 `assignments.assigned_by`、`audit_logs.actor_id` 等 FK 与展示。没有密码，没有会话 |
