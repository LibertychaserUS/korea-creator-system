# 接口说明

API：Hono，`apps/api`，默认 `:7100`。路径与权限的唯一权威是 `packages/kcs-contract/src/api.ts`（`API` 常量）；黑盒测试 `tests/blackbox` 与前端都从那里取路径。`GET /api/openapi.json` 输出汇总。

状态码约定：401 未登录，403 无权限，404 不存在或不可见，409 冲突，400 参数错误，200 / 201 成功，202 已入队。错误体 `{ error: { code, message } }`。

### 错误码

| HTTP | `error.code` | 何时 |
|---|---|---|
| 401 | `AUTH-LOGIN` | 没带或带了失效的会话 |
| 403 | `AUTH-DENIED` | 有会话但角色不够，或账号没有 KCS 分工 |
| 400 | `VALIDATION` | 请求体不是合法 JSON（`message: invalid_json`）；或字段不合规（`invalid_body` 等），此时带 `fields: [{ path, message }]`，如 `displayName` 为空、`followers` 为负、`categories` 里有不存在的分类 |
| 400 | `SOURCE-INVALID` | 抓取参数不合法：未登记的来源、非 30 / 90 天窗口、临时 URL |
| 404 | `NOT-FOUND` | 对象不存在或对你不可见。对不存在的博主 / 分类 / 项目 / 分派做写操作也是 404，**不写审计** |
| 409 | `JOB-STATE` | 任务 / 搁置记录当前状态不允许该操作（如取消已结束的任务） |
| 409 | `CONFLICT` | 唯一性冲突：重复分派同一博主（`already_assigned`）、`creatorKey` 已存在 |
| 413 / 415 | `UPLOAD-TOO-LARGE` / `UPLOAD-TYPE` | 见「上传限制」 |
| 500 | `INTERNAL` | 服务端缺陷；参数问题不应落到这里 |

- 先鉴权后读体：未登录或无权限时，即使请求体是坏的也先得到 401 / 403。
- 写接口的请求体用 zod 校验（`apps/api/src/http/body.ts`），未知的附加字段忽略。
- 筛选方案校验失败时，除 `error.fields` 外仍保留 `errors: string[]`（`kcs.query.errors.*` 的键），供选人端直接翻译。
- 批量分派先逐个检查再写：其中任一博主不在池内，整批都不写（400 `VALIDATION` / `not_in_pool`）。

## 认证

身份在 TinyShip（better-auth）。API 自己没有登录接口。

```
浏览器 ──POST /__login（本端 Nitro）──▶ auth.api.signInEmail ──▶ Set-Cookie better-auth.session_token
                                                              └─▶ Set-Cookie kcs_session=<token>（非 httpOnly，供前端取 Bearer）
前端 useApi ──Authorization: Bearer <token>──▶ API requireAuth
                                                └─ verifySession(token)：GET {AUTH_BASE_URL}/api/auth/get-session
                                                   → { user } → role = roleFromIdentity(user.role)
                                                     KCS 五角色原样；TinyShip `admin` → platform_admin；
                                                     其他（如管理员开通但未分工的 `user`）→ 无角色 → 处处 403 AUTH-DENIED
                                                   → 正缓存 10s（`SESSION_CACHE_MS`），未命中负缓存 5s；有角色才 upsert users 镜像
退出 ──POST /__logout──▶ auth.api.signOut，清两枚 cookie
```

- `AUTH_BASE_URL`：任一工作端的源站（四端共用同一 TinyShip 库，谁校验都一样）。
- 退出：TinyShip 立刻撤销；API 侧最迟 `SESSION_CACHE_MS`（默认 10s）后拒绝旧 token。
- 公开注册已关闭：`POST /api/auth/sign-up/email` 一律 400，不建账号、不发会话；社交 / 手机验证码 / 微信登录也只认已开通的账号。账号只能由管理员开通（`pnpm db:seed:auth` 或 better-auth admin `createUser`）。
- 没有分工的账号（开通了但没被分配 KCS 角色）：`/__login` 落 `/denied`，API 一律 403 `AUTH-DENIED`（含 `/api/auth/me`），不会被当成只读选人。
- 跳转只拼站内相对路径：`/__login` 的 `locale` 只认 `zh-CN` / `en` / `ko`，其他值（如 `/evil.example.com`）一律按 `zh-CN` 处理；宣传站交接的目标源站只取服务端配置（`KCS_*_URL`），不读请求里的地址。
- `kcs_session` 在 `NODE_ENV=production` 时带 `Secure`（`SameSite=Lax`，暂保持非 httpOnly，前端要读它拼 `Bearer`）；因此生产必须走 https（浏览器对 `http://localhost` 例外）。
- 限速：better-auth 对 `/sign-in/email` 按来源 IP 限 3 次 / 10s，超出 429 并带 `X-Retry-After`。
- `KCS_DEV_TOKENS=1`（非生产）额外接受 `Bearer dev:<email>`，仅供本地 curl 临时用；黑盒与 E2E 都走真实邮箱登录，compose 里不再开启。

### 上传限制

- 只收 PNG / JPEG / WebP / GIF。类型按文件头魔数判定，不信客户端声明：HTML、SVG、PDF 等即使标成 `image/png` 也是 **415** `UPLOAD-TYPE`；声明了非图片类型的真图片同样 415。
- 单个文件上限 **5 MB**，超出 **413** `UPLOAD-TOO-LARGE`；超大请求体在读完之前就被拒。先校验登录与角色：未登录 401、无权限 403，不会先返回 413。
- 存储：配置了 S3（`S3_ENDPOINT` + `S3_ACCESS_KEY`）时字节只在 S3，Postgres `assets` 只存元数据（`bytes` 为空）；未配置时字节落 Postgres，由 `/api/assets/raw/*` 读回。对象键带按真实类型得出的扩展名（`avatars/<uuid>.png`）。
- 读回 `/api/assets/raw/*`：再按字节判定一次类型，不是四种图片之一（含修复前存进来的旧行）一律 404；响应头固定 `Content-Type: <判定出的图片类型>`、`X-Content-Type-Options: nosniff`、`Content-Disposition: inline`、`Content-Security-Policy: default-src 'none'`。
- 运营端新建博主页在上传前先按类型 / 大小拦一次，失败时给三语人话提示（`kcs.panel.uploadTooLarge` / `uploadWrongType` / `uploadFailed`）。

## 响应形状速查

```ts
// 池行 / 分派行
QueryResultRow = QueryRow & { tier, cohort: { source, tier, size }, percentiles: { [key]: { percentile, band } }, flags: { key, tone }[] }

// 快照
MetricSnapshot = { id, creatorId, source, window, fetchedAt, jobId, metrics: CreatorMetrics }

// 来源链接
CreatorSourceLink = { source, externalId, firstSeenAt, lastSeenAt }

// 任务进度
IngestJobProgress = { status, pagesDone, cursor, quotaUsed, attempts, nextRunAt, error }
```
