## 1. 产品目标（本系统）

本系统不是「清洗某一张平台导出表的 Demo」。本系统是**双边选人系统**：

1. **我们（或合作运营）把人收进来并整理好**——手工录入，或由后台发起一条**已配置、限速、可审计**的自动入库任务。
2. **选人的人（选人公司，或我们自己选人）方便地挑人**，并把挑中的人**分配到具体项目**。
3. **开发运维能看见任务健不健康**——队列、失败、源是否可用。不是选人界面。

成功标准（人话）：打开前台，能从整理后的库里把人放进一个项目，并改状态；打开后台，能解释这些人从哪来、哪条任务成功或失败。

### 1.1 历史 Demo（非本产品）

V1/v2 文档包与旧 FastAPI `v8a-dashboard` 是课堂/阶段 **Demo**：蒲公英 Excel → 规则分 → AI 解释 → 导出。只证明「表可以进系统」。**不是本产品的作业定义，也不再当 Section 1。** 字段名可当某一种 Source 适配器的参考。IMOK / V3 三角色平台是另一个产品，本仓不做。

## 2. 谁用 · 三工作区

| 角色 | 工作区 | 路由根 | 要完成的事 |
|------|--------|--------|------------|
| 选人 | 前台 | `/{locale}/select` | 浏览整理后的人才库，筛人，分配/移出项目，改三态 |
| 运营录入 | 后台 | `/{locale}/ops` | 录人、导文件、开自动任务、校对、发布到前台池 |
| 开发运维 | 后台 | `/{locale}/dev` | 看 Source/Job 健康、失败、队列、审计。不挑人、不改分配 |

`locale ∈ {zh-CN, en, ko}`。产品 UI 去掉 TinyShip 营销句。

**可见性**

- 前台只看见 **已发布（released）** 的 Talent。看不到录入草稿、原始文件、Job 失败栈。
- 运营看全部 Talent 与 Job 业务结果；默认**不写**别人的 Assignment。
- 运维看 Job/Source/健康/审计；**不写** Talent 业务字段、不分配项目。
- 越权 → `AUTH-DENIED`，不返回未发布数据。

选人可以是外部选人公司，也可以是我们自己用同一个前台选——M1 一个 Org 即可。

---

## 3. 范围内 / 范围外

### 3.1 M1（最薄可挑可分）

- 一条入库路径成立即可验收：**手工录入/文件导入**，**或**一条已配置自动 Job 入库（两条都做屏幕；至少一条跑通）。
- 入库后的人经整理（去重键、必填齐）→ **发布**到前台池。
- 选人建 **一个** Project，分配 / 移出，状态 `candidate | assigned | rejected`。
- `/dev` 能看到该次 Job：排队 / 运行 / 成功 / 失败。
- 三语 + 浅色/深色。主路径步骤少，写操作可确认或撤销。

### 3.2 本轮不做

- 把某一平台导出表当成唯一产品；多平台「随便爬」
- 未授权采集、绕过登录/验证码、未配置源的即兴抓取（**架构只允许配置源 + 限速 + 审计**）
- 活动报名、合同、结算、自动私信/群发
- 规则引擎改排名当选人主界面（质量分若有，是后台属性，不挡 M1 分配）
- Harness.io；Ascendia 产品壳

## 4. 领域对象

| 对象 | 是什么 | 避免叫 |
|------|--------|--------|
| **Org** | 使用方组织。M1 一个：我们自己（兼选人）。后期可拆选人公司。 | Brand、广告主 |
| **Talent** | 被挑选的人。键 `talent_key`（稳定外部 id，缺则系统占位键）。有 `status`：`draft \| ready \| released`。 | 蒲公英行、用户、博主 |
| **Source** | 已配置的数据来源：文件导入、授权 API、已登记连接器。含开关、限速、负责人。 | 爬虫脚本、目标站漏洞 |
| **Job** | 一次入库/同步任务。绑定 Source，状态 `queued \| running \| ok \| failed`，有审计（谁开的、何时、条数、错误摘要）。 | 选人筛选器 |
| **Project** | 一次选人容器（战役名、客户名、档期名）。属 Org。 | Campaign（V3 招募） |
| **Assignment** | Talent × Project。`candidate \| assigned \| rejected`。 | 报名、合同 |

关系：Source → Job → Talent（draft/ready）→ 发布 → 前台可见 → Assignment → Project。

质量分 / AI 备注若存在，是 Talent 上的**只读属性**，不决定能不能分配。M1 不要求六维引擎。

---

## 5. 自动调人 / 拉数（架构，不是菜谱）

后台必须能跑 **Job**，而不是只会手贴表格。约束：

1. **只打已配置 Source**。未启用的源不能被 UI「临时填 URL」开跑。
2. **限速与配额**写在 Source 上；超限 Job 失败并可见。
3. **每条 Job 可审计**：操作者、源、起止、写入条数、错误码。`/dev` 只读展示。
4. 适配器在服务端。UI 只选源、确认开跑、看状态。
5. 失败可重试（运维确认）。成功写入的 Talent 不因重试被复制（按 `talent_key` 去重）。

本文不写具体站点步骤、绕过、未授权接口。实现时只接**授权或自有导出**的适配器。

## 6. 交互原则（完备且简明）

每条主路径：从工作区首页到完成 **≤ 4 次明确操作**。每屏 **一个主按钮**。

| 原则 | 落地 |
|------|------|
| 状态清楚 | Talent：草稿 / 可发布 / 已发布。Job：排队 / 运行 / 成功 / 失败。Assignment：候选 / 已分配 / 已拒绝。 |
| 能确认 | 发布、开 Job、分配、拒绝：二次确认或明确提交。 |
| 能撤销 | 移出项目、从拒绝改回候选、Job 未开跑可取消。已成功 Job 不静默回滚数据，只能再开 Job。 |
| 空 / 错齐全 | 每屏：加载、空列表、失败。空态给一个主行动，不堆次要功能。 |
| 不堆 | M1 不做对比墙、地图、营销仪表盘、联系报价。 |

## 8. 交付方法（先图，再一页，最后串）

1. 按屏幕清单用 AI 出 **数十张页面 mockup**（M1 屏浅+深各一；其余浅色一即可）。

## 10. Milestone 1 验收

完成当且仅当（新应用上，不是 archive）：

- [ ] 运营能 **录入一人或导入一文件**，**或**对一条已配置 Source **确认开 Job** 并看到人入库。
- [ ] 整理后 `released` 的人出现在 `/select` 库；`draft` 不出现。
- [ ] 选人创建一项目，分配一人、拒绝或移出一人；状态正确。
- [ ] `/dev` 能看到该 Job 的成功或失败，无密钥明文。
- [ ] 选人打不开 `/ops` 未发布列表；运维不能写分配。
- [ ] 顶栏可切中英韩与浅/深色；产品名不是 TinyShip。
- [ ] 主路径有确认/撤销；空态与错态可见。

### 之后

多家 Org 隔离、更多 Source 适配器、质检队列做深、质量分/AI 备注、短名单导出美化、供给方自助门户。
