**产品一句话：** 我们挑好人——平台运营把达人整理进发布池，选人公司从前台按项目把人挑走并分配。

## 1. 本产品是什么

本系统是**选人方平台**：我们（平台运营）负责把达人收齐、校对、分类，再交给**选人公司**使用。

三件必须同时成立：

1. **前台只出现已经整理好的达人。** 选人公司少步骤、状态清楚、可撤销，把人分配到项目。
2. **后台能说明这些人从哪来。** 运营可手工录入，也可接收自动入库结果并校对。
3. **自动拉数是可配置的入库任务。** 有来源、周期、状态、失败重试、人工抽检。不是某个站点的导出表 Demo。

成功标准：选人公司能在 **3 步内**（进项目 → 筛库 → 分配）把人放进项目；运营能解释库里的人如何入库、如何分类；运维能看见任务健康，而不是替人选人。

## 4. 前台选人（主路径必须 ≤ 3 步）

选人公司不维护库存。主路径只有：

1. **进项目** — 打开或新建一个 Project，进入该项目工作台。
2. **筛库** — 从项目进入发布池，用默认筛 + 多条件缩小名单。
3. **分配** — 确认把人放进当前项目；可从项目移出以撤销。

详情页、筛选抽屉、确认框都是这 3 步的附属，不另开第四条业务步。运营录入与运维监测**不准**做进前台导航。

前台默认：只看 `released`、排除「黑名单」。默认排序：评分高→低，同分按粉丝量高→低。空结果只给「清空筛选」，不给录入入口。

## 5. 达人分类（多标签）

分类是 Creator 上的**多标签**，不是单选文件夹。运营可启用/停用、改显示名、新增自定义分类。系统内置不可删除，可停用（停用后不再出现在新打标里，已打标仍显示）。

| slug | 显示名（zh-CN） | 内置 | 互斥组 | 含义 | 前台 |
|------|-----------------|------|--------|------|------|
| `collaborated` | 合作过的 | 必须 | `coop_history` | 有过合作履历，或运营确认合作过 | 可见、可筛 |
| `never_collaborated` | 没合作过的 | 必须 | `coop_history` | 尚无合作履历 | 可见、可筛 |
| `intending` | 意向中 | 建议内置 | 无 | 正在谈、尚未成交 | 可见、可筛 |
| `blacklist` | 黑名单 | 建议内置 | 无 | 不合作 / 不放出 | **永不进发布池** |
| `stale` | 待更新 | 建议内置 | 无 | 资料过期，运营待补 | 已发布则可见，带角标；默认筛不自动排除 |

规则：

- `coop_history` 组内最多一个。有 `Collaboration` 记录时，系统把该组写成 `collaborated`；删除全部履历后写成 `never_collaborated`。运营可手工改，与履历不一致时后台显示「标签与履历不一致」，**不挡发布**。
- 其他分类可与 `coop_history` 叠打（例：合作过的 + 意向中；合作过的 + 黑名单）。
- 自定义分类：运营新增，默认前台可见、可筛。若需对前台隐藏，打「仅后台」开关。
- 列表筛分类：同一字段多选为 **OR**，与其他字段 **AND**。

## 6. 筛选 + 排序（SSOT）

不同字段之间 **AND**。同一多选字段内部 **OR**。区间含端点。报价筛的是与 Creator 当前 `Price` 区间**有重叠**。可合作时间筛的是与 Creator 窗口**有重叠**。

### 6.1 字段

| 字段 | 键 | 控件 | 前台库 | 后台库存 | 排序 |
|------|----|------|--------|----------|------|
| 分类 | `categories` | 多选标签 | 是（无黑名单选项；黑名单人根本不在池里） | 是（含全部） | 否 |
| 粉丝量 | `followers` | 数字区间 | 是 | 是 | 可 |
| 是否合作过 | `has_collaborated` | 是 / 否 / 不限 | 是 | 是 | 可（合作优先） |
| 合作次数 | `collab_count` | 整数区间 | 是 | 是 | 可 |
| 合作品牌 | `collab_brands` | 包含（多关键词 OR） | 是（品牌名） | 是 | 否 |
| 报价 | `price` | 金额区间 + 币种 | 是 | 是 | 可（按最低报价） |
| 地区 | `regions` | 多选 | 是 | 是 | 否 |
| 品类 | `verticals` | 多选 | 是 | 是 | 否 |
| 可合作时间 | `available` | 日期区间 | 是 | 是 | 可（窗口开始日近→远） |
| 评分 | `rating` | 区间（0–5） | 是 | 是 | **前台默认** |
| 发布状态 | `status` | `draft \| ready \| released` | 否（恒为 released） | 是 | 否 |
| 源任务 | `ingest_job` | 任务 id / 状态 | 否 | 是 | 否 |
| 最近入库 / 更新 | `updated_at` | 时间 | 否 | 是 | **后台库存默认** |
| 仅看待校对 | `needs_review` | 开关 | 否 | 是 | 否 |

`has_collaborated` 由 `Collaboration` 条数 > 0 派生，不用分类标签代替。分类「合作过的 / 没合作过的」用于浏览；筛「是否合作过」用派生值。

评分是运营维护的 0–5（一位小数），**不是**旧 Demo 的六维规则引擎。无评分的人排在有评分的人后面，再按粉丝量。

### 6.2 各列表页默认

| 列表屏 | 默认筛选 | 默认排序 | 空结果 |
|--------|----------|----------|--------|
| `SEL-LIBRARY` | 已发布；排除黑名单（硬排除）。其余不限 | `rating`↓，同分 `followers`↓ | 「当前条件下没有达人」+ 主按钮「清空筛选」。无录入入口 |
| `SEL-PROJECT` 已分配名单 | 本项目 Assignment；默认不限状态 | 最近分配时间↓ | 「还没有人」+ 主按钮「从库选人」 |
| `SEL-PROJECT-LIST` | 本司未归档项目 | 最近更新↓ | 「还没有项目」+ 主按钮「新建项目」 |
| `OPS-CREATOR-LIST` | 全部状态；默认不含已停用自定义分类的隐藏项 | `updated_at`↓ | 「库存为空」+ 「录入达人」或「去看入库任务」 |
| `OPS-REVIEW` | `needs_review = true` | 入库时间↓ | 「没有待校对」+ 回库存 |
| `OPS-CATEGORY` | 内置在前，自定义在后 | 内置优先，然后名称 | 无（内置至少两条） |
| `ING-JOB-LIST` | 不限状态 | 创建时间↓ | 「还没有任务」+ 「配置任务」 |
| `DEV-JOBS` | 不限；失败行高亮 | 最近更新↓ | 「还没有任务」；不给出选人入口 |

多条件生效后，筛区显示已选芯片，可单颗清除。清空筛选恢复该页默认，不恢复用户上次的自定义排序（排序保持当前列，直到用户改）。

## 7. 前台库 vs 后台库存（字段差）

同一 Creator，两套可见字段。前台**没有**「脏数据模式」。

| 字段 | 前台 | 后台录入 | 说明 |
|------|------|----------|------|
| 显示名、头像、地区、品类、粉丝、评分 | 是 | 是 | 展示用 |
| 分类（除黑名单） | 是 | 是 | 前台不见黑名单其人 |
| 合作次数 / 品牌摘要 / 是否合作过 | 是 | 是 | 前台见摘要；后台见每条 Collaboration |
| 当前报价区间 | 是 | 是 | 后台另见历史报价、有效期 |
| 可合作时间 | 是 | 是 | — |
| `status`（draft/ready/released） | 否 | 是 | 前台能看见 = 已发布 |
| 源、IngestJob id、上次拉数时间 | 否 | 是 | 监测页见同一 Job 的排障向摘要 |
| 原始入库痕迹、缺字段、校对备注 | 否 | 是 | 未通过校对不得发布 |
| 失败栈、适配器内部名、密钥 | 否 | 否（监测可见无密钥摘要） | 任何业务页不得打密钥 |

发布规则：必填齐（显示名、至少 1 个地区或品类、粉丝或「粉丝未知」显式标记）且未打黑名单，运营点一次「发布」。可撤回为不发布；撤回后前台立即不可见，已有 Assignment 保留并标「已不在库」。

## 8. 后台三块

### 8.1 运营录入 ` /ops `

运营如何把人变成发布池里的人：

- **手工录入 / 编辑** — 一人一表，分类、报价、履历、可合作时间、评分。
- **接收自动结果** — IngestJob 写入的人默认 `draft` + `needs_review`。运营抽检或逐条校对后 `ready`，再发布为 `released`。
- **维护分类** — 内置可改显示名；可新增自定义分类。
- **发布 / 撤回** — 二次确认。撤回可撤销（再发布）。

录入主路径步骤见 UX-FLOWS「后台录入」。不在本区做选人分配。

### 8.2 开发运维监测 ` /dev `

开发/运维只看系统健不健康：

- 总览：进程、最近一次成功/失败 Job、源是否启用。
- 任务表：排队 / 运行 / 成功 / 失败；失败高亮。
- 单任务：阶段、错误摘要、重试入口（运维）。
- 管道：Source → Job → 写入 → 待校对 → 已发布 的卡点数字。

禁止：达人筛选器当工作台、推荐按钮、改分配、改报价。密钥只显示「已配置 / 未配置」。

### 8.3 自动拉数 ` /ingest `

产品对象是 **IngestJob**，不是「去某站抓人」的操作手册。

一条 Job 必须能说清：

| 项 | 产品含义 |
|----|----------|
| Source | 已登记、已启用的来源。未启用不能开跑 |
| 适配器 | 服务端已实现的源类型（如：授权 API、已登记连接器、文件投递）。UI 只选类型与已有连接，不填未登记地址 |
| 周期 | 手动一次，或 cron 式周期（每日/每周/自定义） |
| 状态 | `queued \| running \| ok \| failed \| cancelled` |
| 配额 | 写在 Source 上；超限 → Job `failed`，原因可见 |
| 失败 | 摘要 + 可重试（运维确认）。按 `creator_key` 去重，重试不复制人 |
| 抽检 | 成功写入后进入运营待校对；抽检比例可配，默认抽 10% 或至少 1 人 |

约束（硬）：

1. 只打已配置 Source。UI 不能「临时贴一个网页地址就开跑」。
2. 限速与配额在 Source 上，不在对话里现场发明。
3. 每条 Job 可审计：谁开的、哪个源、起止、写入条数、错误码。`/dev` 只读同套数据。
4. 本文与实现说明都**不写**如何突破站点、绕过登录/验证码、未授权接口。适配器只接授权或自有投递。

## 9. UI/UX 原则（完备且简明）

**完备：** 每条主路径必须同时有——入口、进行中、成功、失败、空态、权限不够。缺一项 = 该路径未完成。

**简明：**

- 选人主路径 ≤ 3 步（进项目 → 筛库 → 分配）。
- 每屏一个主按钮。
- 写操作可确认或可撤销：发布、撤回、分配、移出、开 Job、取消未开跑 Job。
- 已成功 Job 不静默回滚已写入的人；要改数据走录入或再开 Job。
- 前台不塞录入、不塞监测、不塞管道图。

**状态词（统一，禁止同义换牌）：**

| 对象 | 状态 |
|------|------|
| Creator | `draft` 草稿 / `ready` 可发布 / `released` 已发布 |
| Assignment | `assigned` 已分配 / `rejected` 已拒绝（移出 = 删除 Assignment，可再分配） |
| IngestJob | `queued` 排队 / `running` 运行 / `ok` 成功 / `failed` 失败 / `cancelled` 已取消 |

**语言与主题：** `zh-CN` / `en` / `ko`；浅色/深色正文对比达到可读（WCAG AA）。切换语言只换 chrome。显示名、手写备注、品牌名保持原文。

## 10. 范围内 / 范围外

### 10.1 M1（最薄可挑可分）

- 运营能手工录入一人，并发布到前台。
- `/ingest` 能对一条**已配置** Source 开 Job（无授权源时，用「文件投递」Source 走同一套 Job 状态机验收）。
- 分类内置「合作过的 / 没合作过的」；建议三条可先做成内置。
- 前台 3 步：进项目 → 筛库（§6 字段可用）→ 分配 / 移出。
- `/dev` 能看到该 Job 成功或失败，无密钥明文。
- 三语 + 浅色/深色。主路径状态六件套齐全。

### 10.2 本轮不做（非目标）

- 把本产品做成「某平台导出表 → 规则分 → 导出」的筛选 Demo（含旧蒲公英 Excel Demo）
- 未授权采集、绕过登录/验证码、未配置源的即兴抓取
- 活动报名、合同、结算、自动私信/群发
- 六维规则引擎当选人主界面；质量分若以后做，仍不挡分配
- 选人公司自助录入库存（那是我们运营的事）
- Harness.io；Ascendia 产品壳；TinyShip 宣传落地页

## 12. Milestone 1 验收

在新应用上（不是 archive）同时成立：

- [ ] 运营手工录入一人，发布后出现在 `/select` 库；`draft` 与黑名单不出现。
