### 1.2 V1 计划书原话（作业定义）

出处：`0501_韩国品牌小红书达人AI筛选Demo_V1计划书`（`/tmp/korea-v1-plan/_txt/0501_…txt`）。

> 核心目标：基于 Excel 完成达人清洗、去重、评分、AI 推荐解释、人工复核与导出。

> 本项目拟制作一个面向韩国品牌合作场景的小红书达人 AI 筛选 Demo。系统基于蒲公英导出的达人 Excel 数据，自动完成数据清洗、达人去重、多维评分、AI 推荐理由生成、人工复核和结果导出，帮助老师或客户快速形成可解释的达人推荐名单。

> V1 阶段强调“可展示、可复核、可导出”的最小闭环，不做账号登录、外部网页抓取、图片视频识别、多平台采集和模型训练。

流水线（计划书「四、系统流程」压缩）：

1. 读 0201 原始 Excel 或 `data/input/current.xlsx`
2. 字段映射、清洗、按 `userId > 小红书号 > 主页 URL` 去重
3. 六维规则分 + 风险扣分 → 最终分、等级、Top10 / Top50 / 全量
4. **仅 Top50** 调 DeepSeek；无 Key / 失败用模板兜底
5. 人工：推荐 / 不推荐 / 待确认 / 已复核；**不直接修改最终分**
6. 导出带时间戳的 Excel / CSV

计划书「六、AI 功能设计」：

> DeepSeek 在 V1 中只承担“解释层”职责，不负责爬网页，不直接修改最终分，也不决定最终排序。排序主要由规则评分产生。

六个轻量面（计划书「七、页面与展示设计」）：控制台、榜单、详情、规则配置、人工复核、导出。图表至少：Top10 条形、六维雷达、等级统计、关键词排行。

## 2. 业务形状：谁供数、谁选人、谁运维

V1 Demo 把「读固定 Excel + 自己评分」做成单控制台。真实系统要拆开三边：

| 边 | 谁 | 干什么 | 不干什么 |
|----|----|--------|----------|
| 供给侧 | 提供达人的公司 | 交出清单和字段（Excel / 表单） | 不给选人公司看脏表；不改别人的项目分配 |
| 作业侧 | **我们运营** | 把清单录进去、校对、过清洗 / 评分 / AI 复核 / 人工确认 | 不代替选人公司做项目短名单（可看，默认不改分配） |
| 需求侧 | 选人的公司 | 只看**已经整理好**的达人，按项目筛选、短名单、分配 / 移出 | 不再做脏数据清洗；看不到原始行、待补队列、任务失败栈 |
| 工程侧 | 开发 / 运维 | 看批次任务、失败、健康、队列、管道 | 不是选人 UI，不改分、不分配项目 |

供给公司可以没有独立门户：M1 **默认由运营代录**（运营录入工作区）。选人公司必须有独立前台。开发运维必须有独立监测面，避免把队列失败塞进选人页。

### 2.1 三个工作区（路由 IA）

语言前缀：`/{locale}/…`，`locale ∈ {zh-CN, en, ko}`。下表省略前缀。

| 工作区 | 路由根 | 给谁 | 产品职责 |
|--------|--------|------|----------|
| 后台 · 运营录入 | `/ops` | 平台运营 | 录入供给清单、校对、清洗结果、规则只读、跑分、AI 复核、人工确认、作业导出 |
| 后台 · 开发运维监测 | `/dev` | 开发 / 运维 | 批次任务、失败、健康、队列、数据管道、Key 是否可用。**不是选人 UI** |
| 前台 · 选人公司 | `/select` | 选人公司策划 | 整理后达人库、按项目选人、分配 / 移出、状态（候选 / 已分配 / 已拒绝）、项目短名单导出 |

产品 UI **去掉 TinyShip 营销文案**（模板 slogan、定价、SaaS 落地页）。宿主框架可以在，品牌名只显示「全球达人情报系统」。

### 2.2 角色与可见性

| 角色 | 工作区 | 可见 | 不可见 / 不可写 |
|------|--------|------|-----------------|
| 供给公司运营 | M1 无独立登录；清单交给平台运营 | — | — |
| 平台运营 | `/ops`（只读可进 `/dev` 健康数字，不操作队列重试以外的工程动作） | 批次、原始清单、清洗结果、待补、全量作业达人、规则、AI、人工、作业导出 | 不改选人公司项目分配（M1 只读项目计数即可） |
| 选人公司策划 | `/select` | 已发布到池的**干净**达人、本司项目、本司分配 | 原始 Excel、待补、排除脏行、供给公司内部备注、`/ops` 校对、`/dev` 失败栈 |
| 开发运维 | `/dev` | 任务、健康、管道、Key 状态（不展示密钥明文） | 不写 Score；不写 ManualReview；不分配项目 |

越权：未知角色 → `AUTH-DENIED`。选人账号打开 `/ops/raw` → 403，不返回脏表 JSON。

## 6. 不变量（评分 / AI / 人工）

1. **规则排序**：`Score.final` / `grade` / `rank` 只由规则引擎 + 当前规则版本产生。
2. **AI 不改分**：`AIReview` 只写 `recommend | cautious | reject` 和文本。来源 `success | fallback | pending | failed`。禁止写回 Score。
3. **人工不改分**：`ManualReview` 四态 + 备注 + 原因标签。禁止写回 Score。
4. **项目分配不改分**：候选 / 已分配 / 已拒绝只写 `Assignment`。
5. **切语言 / 切主题不改分**。
6. 身份键 `creator_key = userId > 小红书号 > 小红书主页URL`，缺则 `missing_key_row_{源行号}`。禁止用 `rank` 当缓存键。
7. Alignment 只统计 `success`：`hard_conflict` = S/A+reject 或 D+recommend；`soft_divergence` = S/A+cautious 等；`fallback` 进 `unknown`，不进真实冲突率。口径见 `docs/01_开发日志.md` 第八阶段 A.1。

六维权重先按计划书：分层 25 / 关键词组合 15 / 韩国品牌 25 / 潜力 20 / 表现 10 / 性价比 5，风险 0～-10。等级阈值 M1 **默认用校准档**（`docs/03_评分规则说明.md`）：S≥80 / A≥65 / B≥50 / C≥35 / D<35。计划书 S≥85 在 0201 上会产生 0 个 S；阈值写在规则页，不写死在 AI。不以复现 0202 排名为硬目标。

## 10. i18n 与主题

- 语言：`zh-CN` / `en` / `ko`。默认 `zh-CN`。第一刀宿主就要切换，禁止中文-only 对外演示。
- 实现：TinyShip `libs/i18n` + Nuxt `@nuxtjs/i18n` `strategy: 'prefix'` + cookie `NEXT_LOCALE`。扩 `ko`。`?lang=` 只薄跳到前缀。细则 `TINYSHIP-REBUILD.md` §5.1。
- 豁免原文：达人昵称、小红书号、原始抓取关键词、手写备注。
- 切语言不重跑排序 / AI 主复核。
