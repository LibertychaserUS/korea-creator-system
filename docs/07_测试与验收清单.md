
## CI（`.github/workflows/kcs.yml`）

push 到 `main` 与所有 PR 都跑。任务名就是 `forge.yaml` 里 `branches.main.required_checks` 的名字，改名要两边一起改；分支保护里勾选这些检查要仓库管理员在 GitHub 设置里手动做。

| 任务 | 跑什么 | 本地复现 |
|---|---|---|
| `contract` | 契约单测 | `pnpm --filter @kcs/contract test` |
| `api` | API 单测，Postgres 16 服务容器（库 `kcs_test`） | `TEST_DATABASE_URL=postgres://kcs:kcs@127.0.0.1:5432/kcs_test pnpm --filter @kcs/api test` |
| `apps (select / ops / dev / marketing)` | 每端 `typecheck` + `build` | `pnpm typecheck:kcs` / `pnpm build:kcs`（或 `pnpm --filter @kcs/app-<端> typecheck`） |
| `blackbox` | 建 `kcs` + `tinyship` 库 → 身份库 `drizzle-kit push` + `db:seed:auth` → 构建并起选人端（登录源站 :7004）、宣传站（交接用例 :7005）→ 起 API（:7100，`KCS_SEED=demo`，千瓜指向替身供应商 :7190）→ `pnpm test:blackbox` | `pnpm blackbox:up && pnpm test:blackbox; pnpm blackbox:down` |
| `api-image` | 只构建 `apps/api/Dockerfile`，不推送 | `docker build -f apps/api/Dockerfile .` |

`scripts/ci/blackbox-up.sh` 全部由 `BLACKBOX_*` 变量驱动（与黑盒用例读的是同一组，见 `tests/blackbox/.env.example`），另有 `BLACKBOX_AUTH_DATABASE_URL`、`BLACKBOX_APPS`、`BLACKBOX_BUILD`、`BLACKBOX_RESET_DB`，说明写在脚本开头。本机端口被占时整组改端口即可，例如 `BLACKBOX_BASE_URL=http://localhost:7120 BLACKBOX_AUTH_URL=http://localhost:7024 BLACKBOX_VENDOR_PORT=7192 …`（注意：内存对象存储的资源链接目前写死 `:7100`，API 不在 7100 时 `07-storage` 的「返回 URL 可取回」一例会红）。日志与 pid 在 `$RUNNER_TEMP/kcs-blackbox`（本地 `/tmp/kcs-blackbox`）。

工作端以生产构建运行，但运行时 `NODE_ENV=development`：前面没有反向代理时没有 `X-Forwarded-For`，better-auth 只在 development / test 下回落到本机 IP 计数登录限速，生产模式下直连会不限速（上线必须在前面放写 `X-Forwarded-For` 的代理）。

浏览器旅程（`e2e/`）暂不进 CI：需要四端 + API + MinIO 同时在线，另行接入。TinyShip 模板应用（next / nuxt / tanstack / docs）的构建在 `ci.yml`，只能手动触发，不出现在 PR 检查里；根 `pnpm test` 仍是模板测试，与 KCS 无关。

## 验收清单（按第一性原理）

### 数据获取
- [ ] 三个适配器都在 `GET /api/ingest/adapters` 出现，`configured` 与 env 一致；无凭证时 `sourceMode = fixture`，界面每处来源徽标带"样例"。
- [ ] 蒲公英 fixture 记录含 `dataSummary` / `fansSummary` / `notesRate` / `fansProfile`，normalize 后 33 个字段中平台不给的保持 `null`。
- [ ] `POST /api/ingest/fetch` 默认 202 入队；worker 在 2 秒内开始；`GET /api/ingest/jobs` 能看到 `pagesDone` / `quotaUsed` 变化。（黑盒 `09-queue`）

### 抽水与搁置记录（黑盒 `10-dead-letters`，spec 见 04）
- [ ] 同一时刻最多一个任务在抓：连提五个，`running` 始终 ≤ 1；抓取中带持有者与租约，跑完交还（`locked_by` / `lease_expires_at` 清空）。
- [ ] 只有抢到顾问锁的进程抽水：同集群起两个循环，页只抓一次、额度只扣一次、原始记录只存一条；`INGEST_WORKER=0` 的进程完全不参与。
- [ ] 进程中途没了：任务停在抓取中，租约未到期时无人接手；到期后被接手并从游标续跑。
- [ ] 平台 4xx / 返回结构不对 → 第一次就搁置（`VENDOR_REJECTED` / `CONFIG_MISSING`），不空转三次；平台 5xx 先退避试满三次再搁置。
- [ ] 搁置的整次抓取带着原参数与游标；「再试一次」新建任务续跑并回填关联；点任务「重试」也会把搁置记录一并结掉。
- [ ] 读不出来的单条留原始内容进搁置，其余照常入库；同条再失败只更新不堆重复；修好后重放直接入库且不花额度；三次仍失败后不再提供重放。
- [ ] 「不再处理」后从待处理消失、再操作 409；筛选参数只认已知取值；错误信息里没有凭证。
- [ ] 处理权限是运维（`dev.retry`），运营只能看，选人 / 只读 403，未登录 401；健康页给出搁置条数与在抓来源。

### 抓取队列（黑盒 `09-queue`，spec 见 04）
- [ ] 入队记录完整：`queued` / 0 页 / 0 额度 / 0 次重试 / 无开始结束时间；`maxPages` 收进 1–100，默认 5；坏参数 400 且不入队。
- [ ] 多页任务逐页翻到游标为空 → `ok`；每页打供应商一次、计 1 次额度；到 `maxPages` 停下并保留下一页游标。
- [ ] 日配额用完 → `partial`：游标保留、`QUOTA_EXHAUSTED`、`nextRunAt` = 次日 00:00（UTC）；到点 worker **自己**从断点续跑到 `ok`；人工 `retry` 也可立刻续跑，`attempts` 归零。
- [ ] `quota = 0` 等于暂停该来源：任务立刻 `partial`，一页都不抓。
- [ ] 演示数据（无凭证）不消耗日配额：`quotaUsed` 为 0，`ingest_source_usage` 不变。
- [ ] 同一来源一次只跑一个任务、先来先跑；`rate_limit = 6` 时第 7 次调用等约 10 秒。
- [ ] 供应商持续 500：2 秒、4 秒退避后第 3 次仍失败 → `failed`、`SOURCE_UNAVAILABLE`、有结束时间；抖一次就恢复 → `ok` 且 `attempts = 1`；失败任务重试后 `attempts` 归零。
- [ ] `queued` / `running` 可取消 → `failed` + `cancelled`，worker 在页边界停下不再打供应商；取消后保留页数与游标，重试从断点续跑；`ok` 的任务取消 / 重试都是 409 `JOB-STATE`。
- [ ] 权限：提交与取消归运营（`ingest.write`），重试归运维（`ingest.retry`），选人 / 只读处处 403；取消与重试都写审计。

### 转换层与指标
- [ ] 原始 `0` 中位数 / 报价 → 界面"—"，不是 0。
- [ ] `health` 来自 `lowActive` / `isActive`，不从其他字段推。
- [ ] 每次 ingest 写一条 `creator_metrics_history`；`creators.metrics` 等于最新一条；锁定（`metricsLocked`）后不覆盖。
- [ ] 蒲公英与千瓜记录共享小红书号 → 一个 creator、两条 `creator_sources`、两条历史；详情页"数据来源"卡两行。

### 分位与筛选方案
- [ ] 分位在 `source × tier` 内计算：两源同量级各自 P 值互不影响；`cohort.size` 与实际人数一致；悬停显示"同源同量级 N 人"。
- [ ] 样本 < 2 时不给分位（`band` 为空，不点亮圆点）。
- [ ] 新建方案：条件 CPE ≤ 3 + 健康 = 优秀 + 腰部 → 表格只剩满足的行；高亮阈值命中显示对应色；显示列与方案一致；刷新后方案仍在（已保存）。
- [ ] `validateSavedQuery` 拒绝未知指标键 / 反向区间，API 返回 400 与字段错误。

### 身份与权限
- [ ] 五个种子账号能在任一工作端登录（TinyShip），`GET /api/auth/me` 返回对应 KCS 角色。（黑盒 `00-login`）
- [ ] 密码错 / 邮箱不存在回应一致（401，不区分），邮箱格式错 400；连续猜密码 429。（黑盒 `00-login`）
- [ ] 公开注册的账号没有 KCS 角色：`/__login` 落 `/denied`，API 处处 403，看不到博主库。（黑盒 `00-login`）
- [ ] `selector_viewer` 打开运营端 → `/denied`；`ops` 调 `/api/select/projects/:id/assignments` → 403。
- [ ] 退出后 `kcs_session` 与 better-auth cookie 都被清，再访问工作端跳登录；旧 token 在 TinyShip 立刻失效，API 最迟 10s 拒绝。（黑盒 `00-login`）
- [ ] 生产模式（`NODE_ENV=production`）下 `KCS_DEV_TOKENS=1` 被拒绝。

### 界面
- [ ] 四端 × 三语 × 浅深 × 桌面 / 移动 截图无 console 错误、无 HTTP ≥ 400、无横向溢出。
- [ ] 池表在 8+ 列时用 `dense` 模式不换行；移动端卡片优先显示排序键。
- [ ] 详情页趋势卡：30 / 90 切换重新请求；CPE 下降显示绿色（`better: 'low'`），粉丝上升显示绿色。
