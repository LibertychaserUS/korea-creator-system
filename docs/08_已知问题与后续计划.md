## 队列与运行

| 问题 | 现状 | 计划 |
|---|---|---|
| 令牌桶在内存 | 只有持锁进程在抽，所以不会多副本叠加；但重启 / 换持锁进程后清零，最坏多打一分钟的量 | 配额已在表里，速率需要跨重启时下沉到表 |
| 每日清理的「上次执行时间」在内存 | 持锁进程每次（重新）拿到锁就先清一次；删除是幂等的，只是重启频繁时会多跑几次 | 需要严格一天一次时把时间记到表里 |
| 停机不打断进行中的平台调用 | 当前这一页的请求要么返回、要么等到 `SHUTDOWN_TIMEOUT_MS`；超时后退出，任务靠租约过期被接手（这一页可能重抓一次，按次计费） | 适配器 `fetch` 接 `AbortSignal` |
| 没有定时抓取 | 只有手动入队 + `partial` 自动续跑 | `ingest_jobs.schedule` 已有列，加 cron 表达式与调度器 |

## 身份

| 问题 | 现状 | 计划 |
|---|---|---|
| API 每次校验都要问 TinyShip | 10s 正缓存（`SESSION_CACHE_MS`）+ 5s 负缓存，最多 5000 条（`SESSION_CACHE_MAX`） | 若延迟敏感，改为 API 直连 tinyship 库读 `session` |
| 角色是全局的 | `user.role` 一个值 | 需要"某选人公司只看自己项目"时在 `can()` 之上加 org 维度（`users.org_id` 已有） |
| 没有自助注册 / 找回密码入口 | 公开注册在 better-auth 配置里关闭（邮箱 / 社交 / 手机 / 微信都不建新用户）；账号由管理员在 TinyShip 侧建（`db:seed:auth` 或 admin 插件） | 需要自助开户时另做邀请制，不重新打开公开注册 |

## 数据库与接口

| 问题 | 现状 | 计划 |
|---|---|---|
| 深页跳转仍走偏移量 | 上一页 / 下一页已是签名游标；跳到第 N 页是 `OFFSET`，5 万人跳到最后一页约 124 ms（05「分页」压测） | 数十万级时再按压测决定是否做锚点缓存 |
| 发布一人要重排整组 | 组内 9000 人时一次发布约 0.9 秒（组锁内） | 组再大时改成只重排受影响的粉丝邻域 |
| 游标密钥缺省随进程随机 | 没配 `KCS_CURSOR_SECRET` / `BETTER_AUTH_SECRET` 时每次启动换密钥，旧游标 400、前端改按页码重取 | 部署时配置 `KCS_CURSOR_SECRET`（k8s 清单已留可选项） |
| 迁移 `0002` 无条件删 `"user"` | 已在所有环境执行过，不能再改；新的 `0011` 已改成先看表形状（有 `email_verified` 列就是 TinyShip 的表，不动） | KCS 库与 TinyShip 库保持分开 |
| 没人用的旧列还在 | `creators.available_from` / `available_to`、`prices.valid_until` 没有读写方 | 确认无外部报表依赖后单独迁移删除 |
| `/api/kcs/creators`、`/api/kcs/assignments` 是旧别名 | 不在契约 `API` 里，前端不用，只有 `errors.test.ts` 覆盖 | 确认无外部调用后下线 |
| `libs/panel/utils/demo-data.ts` 无人引用 | 仍是旧的下划线字段 | 下次动 `libs/panel` 时删 |

## 界面

| 问题 | 现状 | 计划 |
|---|---|---|
| 趋势卡只有四个指标 | 粉丝 / 阅读中位数 / 互动率 / CPE | 让方案 `columns` 决定趋势卡显示哪些 |
