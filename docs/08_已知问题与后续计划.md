# 已知问题与后续计划

只记录当前架构下未收口的事。已修的删掉，不留历史。

## 数据源

| 问题 | 现状 | 计划 |
|---|---|---|
| 千瓜 / 新红没有公开接口文档 | 适配器保留供应商导出口径的中文列名 + 常见英文别名作默认路径，真实路径由 `QIANGUA_FIELD_MAP` / `XINHONG_FIELD_MAP`（JSON）覆盖 | 合同签下后把真实字段表写进 env，跑一次 `sync=1` 对照 `creator_raw` 校验；不改代码 |
| 蒲公英官方开放平台文档在合作方登录后 | `PGY_GATEWAY=official` 的请求体按网页版 solar 接口整理，未用真实凭证验证 | 拿到官方凭证后跑 `apps/api/tests/pugongying.test.ts` 的 official 用例对照真实响应 |
| 付费网关按次计费，空结果也扣 | 每页计入 `quota_used`；蒲公英详情补全内部的 4 次调用目前按一页计一次，账单可能低估；`PGY_ENRICH` 默认关 | 适配器 fetch 返回本页实际调用次数，worker 按此记账；运营端数据源卡显示今日调用 / 配额 |
| 类目 / 地域取值必须与平台字典一致 | 表单是自由输入 | 把 `get_blogger_filter_options` / `content/tag_tree` 结果缓存成字典接口，表单改下拉 |
| 尚未映射的蒲公英字段 | `inviteReply48hNumRatio`、`responseRate`、`kolAdvantage`、`payFansUserRate30d`、直播、长尾阅读 | 需要时加到 `METRIC_FIELDS` + `normalizePugongying` |

## 队列与运行

| 问题 | 现状 | 计划 |
|---|---|---|
| worker 在 API 进程内 | 单实例足够（k8s `replicas: 1`）；多副本会重复取任务 | 多副本前加 advisory lock / `FOR UPDATE SKIP LOCKED` 领取，或独立 worker 进程 |
| 令牌桶在内存 | 重启清零；多副本各自一桶 | 同上，配额已在表里，速率可下沉到表 |
| 没有定时抓取 | 只有手动入队 + `partial` 自动续跑 | `ingest_jobs.schedule` 已有列，加 cron 表达式与调度器 |

## 身份

| 问题 | 现状 | 计划 |
|---|---|---|
| API 每次校验都要问 TinyShip | 30s 缓存 + 5s 负缓存 | 若延迟敏感，改为 API 直连 tinyship 库读 `session` |
| 角色是全局的 | `user.role` 一个值 | 需要"某选人公司只看自己项目"时在 `can()` 之上加 org 维度（`users.org_id` 已有） |
| 没有自助注册 / 找回密码入口 | 账号由管理员在 TinyShip 侧建（`db:seed:auth` 或 admin 插件） | 需要时打开 better-auth 的 sign-up 页 |

## 界面

| 问题 | 现状 | 计划 |
|---|---|---|
| 趋势卡只有四个指标 | 粉丝 / 阅读中位数 / 互动率 / CPE | 让方案 `columns` 决定趋势卡显示哪些 |
| 分位 cohort 只在悬停可见 | `MetricValue` title | 池表头加一次性说明"分位按同源同量级" |
| 方案编辑器没有"另存为" | 只能新建 / 编辑 | 加复制 |
| 三语文案由人工维护 | 键集合一致性靠脚本检查 | CI 里加键集合校验 |

## 不做

- 自建抓取（路线 C）。
- 任何形式的综合评分、权重、等级。
- 用默认值补平台不给的数字。
