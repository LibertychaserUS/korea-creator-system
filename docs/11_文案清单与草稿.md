# 11_文案清单与草稿

本文档为 KCS（韩国品牌 × 小红书博主数据系统）的文案规范、术语对照表、三语界面文案清单以及宣传站（Landing Page）完整文案草稿。一切文案均严格基于“**有参数的爬虫 + 转换层 + 指标筛选方案**”新架构编写，彻底废除旧版“六维综合加权评分、算法推荐分、权重打分”等概念。

---

## 一、术语对照表（Terminology Table）

在所有端（宣传站、运营端、运维端、选人端）与用户沟通中，统一人群术语与核心业务概念。面向主要用户群（**品牌选人同事、运营人员**），文案直接、朴素、客观，杜绝虚假算法承诺。

| 中文规范术语 (zh-CN) | 英文规范术语 (en) | 韩文规范术语 (ko) | 禁用旧词 / 混淆表达 | 概念定义与业务口径 |
|---|---|---|---|---|
| **博主** | Creator | 크리에이터 | 达人 / 网红 / KOL / 账号 | 小红书内容创作者与合作对象，统一称“博主” |
| **数据源** | Data Source / Source | 데이터 소스 | 平台接口 / 抓取库 | 蒲公英官方（路线 A）与第三方供应商（千瓜/新红，路线 B） |
| **抓取任务** | Ingest Job / Fetch Job | 수집 작업 | 拉数任务 / 采集任务 / 爬虫作业 | 运营人员填参后入队的后台异步作业，由 worker 按频控与配额执行 |
| **转换层** | Transform Layer | 변환 계층 | 数据清洗层 / 评分计算引擎 | 将平台或供应商原始 solar JSON 映射为标准结构，不猜不补 |
| **指标** | Metric / Metrics | 지표 | 分数 / 维度分 / 评分 | 平台给出的客观字段或纯算术派生比率，无任何加权得分 |
| **量级** | Follower Tier / Tier | 팔로워 구간 / 등급 | 梯队 / 级别 / 咖位 | 按粉丝数划分：头部 (≥50万)、腰部 (5-50万)、初级 (5千-5万)、素人 (300-5千) |
| **健康等级** | Health Grade | 건강 등급 | 账号评分 / 风险分 | 蒲公英官方每月更新：优秀 (excellent) / 正常 (normal) / 异常 (abnormal) |
| **分位** | Percentile Band | 분위 / 백분위 구간 | 排名分 / 竞争力分 | 指标在“同一数据源 × 同一量级”群体中的客观排位 (top10/top25/上半/下半/末段) |
| **筛选方案** | Saved Query / Query | 필터 세트 / 쿼리 | 评分模型 / 推荐规则 / 权重包 | 保存的指标条件 (≥/≤/区间/分位≥) + 排序 + 高亮阈值 + 显示列 |
| **项目** | Project | 프로젝트 | 投放案 / 需求包 | 选人公司用于承载候选名单与投放推进的业务单元 |
| **候选名单** | Shortlist / Board | 후보 명단 / 프로젝트 인원 | 投放入围表 / 达人池 | 选人端分配进特定项目的候选博主集合 |
| **样例数据** | Sample Data / Fixture | 샘플 데이터 (Fixture) | 假数据 / 模拟跑分 | 未配置接口凭证时后端返回的结构对照演示数据，显式标识 |
| **快照** | Snapshot | 스냅샷 | 固化分 / 存档记录 | 每次抓取或发布博主时固化的指标历史数据，只读不可篡改 |
| **身份归并** | Identity Merge | 식별자 병합 | 达人合并 / 多账号关联 | 跨多个数据源时按唯一的小红书号 (xhsId) 归并展示 |

## 二、每个指标（`kcs.metric.*` / `kcs.metricHelp.*`）一句话口径说明

所有指标严格遵循“**平台给什么我们看什么，取不到保持 —，绝不脑补**”原则。

| 键名 | 指标名称 (zh-CN) | 一句话口径说明（给运营与品牌选人同事） | 取值来源与缺失处理 |
|---|---|---|---|
| `followers` | 粉丝数 | 博主在小红书主页公开展示的累计粉丝总数。 | 来自蒲公英/供应商字段，取不到显示 — |
| `followerGrowth` | 近期涨粉 | 统计周期（近30天或90天）内净增长的粉丝数。 | 来自蒲公英/供应商字段，取不到显示 — |
| `followerGrowthRate` | 涨粉率 | 统计周期内净涨粉数 ÷ 周期开始时的基准粉丝数。 | 派生计算，分母无效或取不到显示 — |
| `readFanRatio` | 粉丝阅读占比 | 日常笔记阅读量中来自已关注粉丝的比例；越低说明自然公域流量越强。 | 来自蒲公英官方字段，取不到显示 — |
| `activeFanRatio` | 活跃粉丝占比 | 近30天内在小红书有打开、浏览等活跃行为的粉丝比例。 | 来自蒲公英官方字段，取不到显示 — |
| `engagedFanRatio` | 互动粉丝占比 | 近30天内与博主笔记产生过点赞、收藏或评论互动的粉丝比例。 | 来自蒲公英官方字段，取不到显示 — |
| `impressionMedian` | 曝光中位数 | 统计周期内日常自然笔记曝光量（千次展示）的中位数。 | 来自蒲公英官方或新红字段，取不到显示 — |
| `readMedian` | 阅读中位数 | 统计周期内日常笔记真实阅读次数的中位数，反映日常自然流量底盘。 | 来自蒲公英/供应商字段，取不到显示 — |
| `interactionMedian` | 互动中位数 | 统计周期内日常笔记（点赞 + 收藏 + 评论）总和的中位数。 | 来自蒲公英/供应商字段，取不到显示 — |
| `likeMedian` | 点赞中位数 | 统计周期内日常笔记单篇点赞数的中位数。 | 来自蒲公英/供应商字段，取不到显示 — |
| `collectMedian` | 收藏中位数 | 统计周期内日常笔记单篇收藏数的中位数；收藏体现强烈的购买与种草意向。 | 来自蒲公英/供应商字段，取不到显示 — |
| `commentMedian` | 评论中位数 | 统计周期内日常笔记单篇评论数的中位数。 | 来自蒲公英/供应商字段，取不到显示 — |
| `coopReadMedian` | 合作阅读中位数 | 经蒲公英报备商业合作笔记的阅读量中位数，直接反映带货公域表现。 | 来自蒲公英官方合作字段，取不到显示 — |
| `coopInteractionMedian` | 合作互动中位数 | 经蒲公英报备商业合作笔记的点赞、收藏与评论中位数。 | 来自蒲公英官方合作字段，取不到显示 — |
| `engagementRate` | 互动率 | 互动中位数 ÷ 阅读中位数（按真实阅读计算，绝不用虚假粉丝数当分母）。 | 派生计算或官方字段，取不到显示 — |
| `retentionRate` | 完播率/3S阅读率 | 图文笔记3秒阅读率或视频笔记5秒播放完成率，反映内容前黄金开篇吸引力。 | 来自蒲公英/供应商字段，取不到显示 — |
| `noteCount` | 发文数 | 统计周期内在小红书平台实际发布的公开笔记总篇数。 | 来自蒲公英/供应商字段，取不到显示 — |
| `viralCount` | 爆文数 | 统计周期内达到爆文标准的笔记篇数（千赞或五千赞以上）。 | 来自供应商字段（蒲公英若无绝对数则保持 —） |
| `viralRate` | 爆文率 | 千赞及以上优质笔记占总发文篇数的比例。 | 来自蒲公英或供应商字段，取不到显示 — |
| `priceImage` | 图文一口价 | 蒲公英报备官方图文合作单篇标准报价（人民币）。 | 来自蒲公英官方报备报价，取不到显示 — |
| `priceVideo` | 视频一口价 | 蒲公英报备官方视频合作单篇标准报价（人民币）。 | 来自蒲公英官方报备报价，取不到显示 — |
| `cpv` | 单次阅读成本 | 图文一口价 ÷ 合作笔记阅读中位数（每个实际阅读花多少钱）。 | 派生除法或官方字段，取不到显示 — |
| `cpe` | 单次互动成本 (CPE) | 图文一口价 ÷ 合作笔记互动中位数；韩妆与美妆投放实操通常以 ≤3 元为优选区间。 | 派生除法或官方字段，取不到显示 — |
| `cpm` | 千次阅读成本 (CPM) | 图文一口价 ÷ 合作笔记阅读中位数 × 1000（千次阅读成本）。 | 派生除法或官方字段，取不到显示 — |
| `collectLikeRatio` | 收藏点赞比 | 收藏中位数 ÷ 点赞中位数；比值越高说明高价值干货与深度种草属性越强。 | 派生计算，点赞为0或取不到显示 — |
| `purchaseIntentCommentRatio` | 求购评论占比 | 评论中含“求链接、怎么买、多少钱、色号、已下单”等真实购买意向词的占比。 | 来自蒲公英官方语义字段，取不到显示 — |
| `trafficSearchRatio` | 搜索流量占比 | 笔记阅读流量中来自主动搜索的比例；越高代表长尾自然流量与心智沉淀越久。 | 来自蒲公英官方流量结构字段，取不到显示 — |
| `trafficRecommendRatio` | 推荐流量占比 | 笔记阅读流量中来自发现页/信息流推荐的比例；越高代表爆发推流潜力越大。 | 来自蒲公英官方流量结构字段，取不到显示 — |
| `trafficFollowRatio` | 关注流量占比 | 笔记阅读流量中来自博主粉丝关注页的比例。 | 来自蒲公英官方流量结构字段，取不到显示 — |
| `readToFollowerRatio` | 读粉比 | 日常阅读中位数 ÷ 粉丝数；高读粉比代表平台算法正在强推，内容穿透力强。 | 派生计算，取不到显示 — |
| `authenticity` | 粉丝真实度 | 第三方数据机构根据账号互动行为与水军特征抽样估算的真实粉丝比例。 | 来自第三方供应商字段（蒲公英不提供保持 —） |
| `coopNoteCount` | 合作笔记数 | 博主在小红书平台累计完成的官方报备商业合作笔记总数。 | 来自蒲公英官方字段，取不到显示 — |

## 三、宣传页（Landing Page）完整文案草稿

宣传页承载产品定位：**客观、严谨、面向运营与选人团队的全球博主情报台**。杜绝浮夸修辞，不承诺“AI精准预测爆款”、“全网唯一转化归因”，有一说一。

### 1. Hero 区域
- **眉题 (Eyebrow)**：`听潮 · 品牌出海选人系统`
- **主标题 (H1)**：`小红书博主数据，回归客观指标。`
- **副标题 (Lead)**：`不发明综合分，不搞黑盒加权。直连蒲公英官方与专业第三方数据源，用有参数的抓取、透明转换层与同量级分位，帮品牌团队选出真正有转化力的博主。`
- **主要行动按钮 (CTA Primary)**：`登录工作台 →`
- **次要行动按钮 (CTA Secondary)**：`了解四大端工作台`
- **产品底线标签 (Pillars)**：`真实源头 · 客观指标 · 同量级分位 · 快照锁存`

### 2. 产品缩影卡片（Hero 预览）
- **卡片标题**：`博主库`
- **卡片副标**：`已发布 · 按 CPE 升序`
- **健康等级门槛**：`健康等级 · 优秀（低活博主硬门槛已排除）`
- **一键动作**：`分派到项目`

### 3. 数据来源与转换层（Data & Pipeline）
- **区块眉题**：`数据源头`
- **区块标题**：`两条路线拉取，一层规范转换。`
- **区块导语**：`平台给什么，系统就呈现什么。派生指标全为公开算术除法，绝不掺杂人工权重打分。取不到的数据保持“—”，不猜不编。`
- **路线 A（官方数据）**：
  - 标签：`蒲公英 · 小红书官方`
  - 说明：`经官方开放平台或企业专线网关直连，返回同一份 solar 标准协议。涵盖曝光/阅读/互动中位数、图文视频一口价、CPE、健康等级、粉丝画像及合作品牌。`
- **路线 B（供应商数据）**：
  - 标签：`千瓜 / 新红 · 第三方供应商`
  - 说明：`企业合同直连接口，支持字段动态映射。提供行业大盘对比、近90天爆文表现、发文频率、粉丝真实度与供应商指数。`
- **转换层透明声明**：`raw JSON → 字段映射表 → CreatorMetrics。原始平台返回原样留存备查，字段口径更新无需改动系统核心代码。`

### 4. 指标怎么读与同量级分位（Cohorts & Percentiles）
- **区块标题**：`指标好与坏，只在同量级同数据源里比。`
- **量级划分（Tier）**：
  - `头部 (Head)`：粉丝数 ≥ 50 万
  - `腰部 (Mid)`：粉丝数 5 万 – 50 万
  - `初级 (Junior)`：粉丝数 5 千 – 5 万
  - `素人 (Amateur)`：粉丝数 300 – 5 千
- **分位逻辑**：不同量级博主之间 CPE 或互动率不可简单横向对比。系统将每个指标与“同一数据源 × 同一量级”的样本群排位（前 10%、前 25%、中上、中下、后 25%），清晰告知“同量级 N 位博主中的相对身位”。不同数据源口径各异，绝不跨源混排。
- **健康等级作为硬门槛**：蒲公英每月 1 日更新的“健康等级”是能否合作的一票否决线。“异常（低活博主）”直接剔除，“正常”审慎评估，不把健康风险通过分数加权稀释。

### 5. 筛选方案（Saved Queries）
- **区块标题**：`用筛选方案替代主观评分。`
- **区块说明**：`选人公司用业务语言定义标准。将“量级 = 腰部 + 健康等级 = 优秀 + CPE ≤ 3 + 收藏/点赞 ≥ 0.8”固化为带版本的筛选方案。全团队一键复用，既沉淀投放标准，又杜绝选人经验流失。`

### 6. 四大工作端介绍（Workspaces）
- **选人端 (Select Desk)**：`博主库筛选、多版本方案切换、候选名单挑人与项目分派。`
- **运营端 (Ops Desk)**：`手动录入与批量导入、参数化抓取任务发起、数据源凭证与字段映射维护。`
- **运维端 (Dev Desk)**：`抓取队列监控、配额耗尽游标留存、失败任务重试与接口健康巡检。`
- **宣传站 (Marketing)**：`产品理念、数据口径与多端访问门户。`

### 7. 底部行动区 (Bottom CTA)
- **标题**：`开启客观透明的博主选人水线。`
- **副标**：`使用工作邮箱登录，系统将根据账号权限直接进入对应工作台。`
- **按钮**：`立即进入工作台 →`

## 五、界面结构改进建议（给前端与产品同事）

文案层已尽全力消除“六维评分、综合加权、旧诗化谜语”，但在前端组件与页面结构层面，仍存在若干文案无法单独修复的结构性问题，需前端同事协助排期调整：

1. **表格表头排序控件（apps/select/pages/index.vue）**：
   - 现存结构：下拉框中仍保留 `kcs.panel.sortRating`。
   - 建议：改为动态绑定当前生效 `SavedQuery` 中设定的排序字段（如按 `cpe`、`readMedian` 等实际指标），而不是一个笼统的排序项。
2. **手机端卡片与紧凑表格的分位标签（libs/panel/components/MetricValue.vue）**：
   - 当前在移动端或小空间下分位只亮圆点，悬浮才显示同源同量级人数。
   - 建议：在博主详情页主要指标旁，增加常驻小角标 `同源同量级 P75 (共 142 人)`，让选人同事一眼判断含金量，无需手动 hover。
3. **数据源抓取任务状态详情抽屉（apps/ops/pages/sources/index.vue）**：
   - 当前任务若处于 `partial`（配额耗尽，保留游标），界面仅显示状态字样。
   - 建议：增加可展开的“游标进度与配额抽屉”，展示当前已消费的 API 配额数、下一批次预计恢复时间 (`nextRunAt`) 以及当前游标页码，提升运营人员心理安全感。
4. **小红书号多来源归并卡片（apps/select/pages/creators/[id].vue）**：
   - 当前若同一博主存在蒲公英与第三方来源，仅在右下角小列表显示 externalId。
   - 建议：在博主详情头部做“数据源版本切换 Tab”，选人同事可对比“官方蒲公英指标 vs 千瓜第三方指标”，并一目了然看清两边数据抓取时间差异。
5. **筛选方案的高亮色彩提示（Query Highlight Tones）**：
   - 方案编辑器里的 `good / warn / bad` 在表格中缺少图例说明。选人新手不明白为何某个数字有彩色背景。建议在表格右上角增加轻量图例提示。
